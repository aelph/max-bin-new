# max-bin-new

**Read this in English: [README.md](README.md)**

Локальный (не публикуемый в AUR) пакет Arch Linux для мессенджера **MAX** (https://max.ru).
Форк AUR-пакета [max-bin](https://aur.archlinux.org/packages/max-bin) с автоматизацией обновлений и **исправлением неработающих аудио- и видеозвонков**.

Пакет бинарный: официальный RPM для EL9 переупаковывается «как есть», без пересборки.

## С AUR-пакетом не работают аудио- и видеозвонки

Если вы поставили MAX из AUR-пакета `max-bin` (или напрямую из RPM) и звонки молча не проходят, тогда как голосовые и видео*сообщения* записываются и отправляются нормально, — причина в следующем.

Звонки обслуживает отдельный процесс, `/usr/share/max/bin/max-service/bin/max-service`, и в Arch он падает сразу при запуске:

```
$ /usr/share/max/bin/max-service/bin/max-service
libsystemd.so.0: version `LIBSYSTEMD_251' not found (required by /usr/lib/libmount.so.1)
```

В RPM встроена `libsystemd.so.0.23.0` из EL9 — она лежит в `bin/max-service/lib64/`, а у `max-service` прописан `RPATH $ORIGIN:$ORIGIN/../lib64`, поэтому встроенная копия перекрывает системную. При этом системный `libglib-2.0.so.0` подтягивает системный `libmount.so.1`, которому нужен символ версии `LIBSYSTEMD_251`, отсутствующий в копии из EL9. Затронуты все установки Arch, так как `util-linux` здесь всегда собран против актуального systemd.

Запись и отправка голосовых и видеосообщений при этом продолжают работать, потому что выполняются в основном процессе `max`, куда `libsystemd` не встроена. Именно поэтому поломку легко не заметить.

**Исправление**, которое этот пакет делает в `package()`, — удалить встроенные копии, чтобы использовались системные библиотеки:

```bash
rm -f "${pkgdir}/usr/share/max/bin/max-service/lib64/libsystemd.so.0"*
rm -f "${pkgdir}/usr/share/max/bin/max-service/lib64/libpcre2-8.so.0"*
```

Напрямую с `libsystemd` в бандле не слинкован никто (проверено через `readelf -d`) — она подтягивается только транзитивно через системный glib, так что удаление безопасно. Встроенная `libpcre2-8.so.0` — та же самая история: из-за неё системный glib печатает `no version information available`. После удаления обеих библиотек `max-service` запускается штатно и звонки работают.

Исправление не привязано к конкретной версии и переживает обновления. Чтобы проверить его после обновления, запустите `max-service` вручную: исправный запуск печатает `RPC port: <номер>` и пути к каталогам настроек, без строк `not found`.

## Как пользоваться

Все действия — одним скриптом:

| Команда | Что делает |
|---|---|
| `./update.sh check` | Сравнивает установленную версию с официальным RPM-репозиторием. Код возврата `10` — есть обновление. |
| `./update.sh` | Полный цикл: `git pull --ff-only` → правит `pkgver` в `PKGBUILD` → `updpkgsums` → `makepkg -f` → перегенерация `.SRCINFO` → коммит `Update <версия>` → `sudo pacman -U` → `git push`. Если новая версия уже подтянута с другой машины, выполняются только сборка и установка, без коммита. |
| `./update.sh notify` | Тихая проверка с уведомлением на рабочий стол (`notify-send`). Используется systemd-таймером. |
| `./update.sh rollback` | Показывает локально сохранённые сборки. |
| `./update.sh rollback <версия>` | Откатывается на указанную сборку (`sudo pacman -U`). |

### Автоматическое уведомление о новых версиях

Юниты `max-update-check.service` и `max-update-check.timer` лежат в `~/.config/systemd/user/`
(**вне репозитория** — при переносе на другую машину их нужно скопировать отдельно).
Таймер срабатывает раз в сутки в 12:00 (плюс случайная задержка до часа) — днём, чтобы
уведомление не пришло ночью незамеченным; `Persistent=true` — пропущенная из-за
выключенного компьютера проверка выполнится при включении. Уведомление отправляется
с важностью `critical`: оно не исчезает с экрана, пока его не закрыть.

```
systemctl --user list-timers max-update-check.timer   # состояние таймера
systemctl --user start max-update-check.service       # проверить вручную
```

Установку скрипт сам не запускает — придёт только уведомление; дальше вручную `./update.sh`.

## Откат

- **На предыдущую локальную сборку:** собранные `.pkg.tar.zst` намеренно накапливаются в корне репозитория — `./update.sh rollback <версия>`.
- **На AUR-версию:** установите `max-bin` из AUR. Пакеты объявляют взаимный конфликт (`conflicts`), поэтому pacman корректно заменит один другим. Обратный переход — `sudo pacman -U max-bin-new-<версия>-*.pkg.tar.zst`.

## Оговорки

- **Неофициальный пакет.** Проприетарный бинарник переупаковывается без каких-либо гарантий; авторы MAX к этому репозиторию отношения не имеют.
- **`sudo` в конце обновления.** `./update.sh` при установке запросит пароль — запускайте в интерактивном терминале. В неинтерактивном окружении всё, кроме установки, выполнится, а `pacman -U` завершится ошибкой — тогда установите пакет вручную.
- **Трафик и место.** Каждое обновление скачивает RPM ~325 МБ; старые сборки (~400 МБ каждая) хранятся для отката — периодически удаляйте лишние.
- **Git-коммит делается автоматически** при каждом обновлении (`Update <версия>`), ещё до установки. Если установка не удалась, коммит уже существует — это нормально: файлы соответствуют собранному пакету.
- **Remote `upstream` (AUR) — только для чтения.** Push отключён (URL `DISABLED`). Не делайте `git pull upstream master` — истории разошлись, будут конфликты в `PKGBUILD`/`.SRCINFO`. Правильно: `git fetch upstream`, посмотреть `git diff master upstream/master -- PKGBUILD` и перенести полезное вручную.
- **Не делайте `git reset --hard upstream/master`** — это единственный сценарий, при котором пропадут `update.sh` и прочие локальные файлы.
- **`.gitignore` устроен как whitelist:** игнорируется всё, кроме явно перечисленного. Новый файл в репозитории нужно сначала добавить строкой `!имя_файла`.
- **Номер версии** (`X.Y.Z.BUILD`) скрипт берёт из имён RPM-файлов в метаданных репозитория; атрибут `ver` там усечён и для сравнения непригоден.
- **Зависимости подобраны вручную** под закрытый бинарник (например, `libxres` нужен для звонков). После крупных обновлений проверяйте запуск приложения и звонки — могут понадобиться новые библиотеки.
- **Проверяйте `max-service` после обновления.** Звонки живут в отдельном процессе, поэтому запуск основного приложения об их работоспособности ничего не говорит. Если в новом RPM появится ещё одна встроенная библиотека, перекрывающая системную, добавьте её в список `rm -f` в `package()`. Найти такие конфликты по всему пакету: `cd /usr/share/max && find . -type f \( -name '*.so*' -o -perm -u+x \) -exec sh -c 'ldd "$1" 2>&1 | grep -q "not found" && echo "$1"' _ {} \;`
- **`notify` молчит, если сеть так и не появилась** — это не ошибка, а защита от ложных уведомлений. Сразу после загрузки (`Persistent=true` запускает пропущенную проверку до подъёма сети) скрипт повторяет попытки до 5 минут.
- **Встроенного автообновления у MAX для Linux нет:** на «родных» RPM-системах обновления приходят через репозиторий dnf. Этот скрипт — эквивалент такого механизма для Arch.
